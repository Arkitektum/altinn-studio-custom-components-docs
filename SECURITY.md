# Security Policy

## Supported versions

This is a static documentation site, deployed from the **latest `main`** via GitHub Pages.
Security fixes are made against the latest `main`.
Please reproduce any issue on the latest `main` (or the live site) before reporting it.

## Reporting a vulnerability

**Please do not report security vulnerabilities through public GitHub issues, pull requests, or discussions.**

Instead, report them privately through GitHub's private vulnerability reporting:

1. Go to the repository's **Security** tab: <https://github.com/Arkitektum/altinn-studio-custom-components-docs/security>
2. Click **Report a vulnerability** to open a private advisory.

Please include as much of the following as you can:

- A description of the vulnerability and its potential impact.
- The affected version / commit and the environment (local dev server or the live site).
- Step-by-step instructions to reproduce, including a minimal proof of concept if possible.
- Any suggested remediation.

### What to expect

- We will acknowledge your report and begin investigating.
- We will keep you informed of progress and let you know when a fix is released.
- Please give us a reasonable amount of time to address the issue before any public disclosure.
  We are happy to credit reporters who wish to be acknowledged.

## Scope and security model

This is a **static, client-side documentation site** that renders the published custom components with example data.
A few properties are relevant when assessing security:

- **No backend, no secrets.**
  The site is built to static files and served by GitHub Pages.
  There is no server, no authentication, and no secrets in the repository.
- **Example data only.**
  All data models and text resources in `src/data` are synthetic demo data and must never contain real or personal data.
- **Rendering published components.**
  Component logic lives in `@arkitektum/altinn-studio-custom-components` and `@arkitektum/altinn-studio-custom-components-utils`.
  A vulnerability in how a component renders likely belongs in one of those repositories — please report it there as well.
- **Build output is committed.**
  The `docs/` folder is generated by `yarn build`; treat it as build artifact, not as a place to hand-edit.

## Dependencies

Build/runtime dependencies include Webpack, highlight.js, and the Arkitektum custom-components packages.
If you find a vulnerability in a dependency, please report it to that project as well, and open an advisory here if this site is affected.
